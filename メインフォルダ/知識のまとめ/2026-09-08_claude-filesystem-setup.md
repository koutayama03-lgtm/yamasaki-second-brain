# ClaudeにObsidian vaultへ直接書き込ませるまでの経緯

## 背景
- Java学習メモをClaudeにまとめてもらい、Obsidian vault（`C:\Users\yamas\Downloads\kouta-room`）に保存したかった
- 以前の別セッションでは「Claudeが直接vaultにファイルを作ってくれた」記憶があったが、今回のセッション（ブラウザ版claude.ai）では最初それができなかった

## 分かったこと

### 1. 環境の違い
- **ブラウザ版 / モバイル版のclaude.ai**：ユーザーのPCのファイルシステムには一切アクセスできない
- **Claude Desktop（PCにインストールするアプリ）**：見た目はブラウザ版とほぼ同じだが、裏側の仕組みが異なり、設定次第でローカルファイルにアクセス可能
- 会話（チャット履歴）自体はどの端末で始めたかに縛られない。始めた端末に関係なく、今どのクライアントから接続しているかで使える機能が決まる
- 設定 →「アカウント」内の「アクティブなセッション」一覧で、今の接続がどのデバイス・アプリか確認できる（例：「Claude Desktop（現在）」の表示）

### 2. Filesystemコネクタ
- Claude Desktopには「Filesystem」という名前の公式コネクタが存在し、指定したフォルダに限定してClaudeがアクセスできるようになる
- 設定手順：設定 →「コネクタ」→ Filesystemを追加 → アクセスを許可するフォルダ（今回は vault フォルダ）を指定
- **コネクタの接続は会話（チャット）ごとに有効/無効が決まる**。新しい会話でないと反映されないケースがある

### 3. ツールの権限設定（つまずいたポイント）
- コネクタ設定内に「ツールの権限」という項目があり、以下の2グループに分かれている
  - **読み取り専用ツール**（list_directory, read_text_file, get_file_info など）
  - **書き込み/削除ツール**（write_file, edit_file, create_directory, move_file など）
- それぞれ「常に許可」「都度確認」「ブロック済み」の3段階で設定できる
- 「読み込み権限を拒否したい」つもりで操作したところ、実際には
  - 読み取り専用ツール → ブロック済み
  - 書き込み/削除ツール → 常に許可
  という、意図と逆の設定になっていた
- 結果として、Claudeが`list_directory`などの読み取り系ツールは使えなくなった一方、`write_file`（新規ファイル作成・上書き）、`edit_file`、`create_directory`、`move_file`が無条件で使える状態になっていた

### 4. 実際にできたこと
- 上記の状態（書き込み/削除ツールが「常に許可」）で、Claudeが直接
  - vault内の「今日やったこと」フォルダに新規ファイル（`2026-09-08_java-study.md`）を作成
  - この「知識のまとめ」フォルダを新規作成
  - このファイル自体の作成
  を実行できることを確認した

## 注意点・今後の運用
- 「書き込み/削除ツール」が「常に許可」のままだと、Claudeが既存ファイルの上書き・編集・移動・削除も無条件でできてしまう状態になる
- 誤操作や意図しない上書きのリスクがあるため、落ち着いたタイミングで「常に許可」ではなく「都度確認」に変更するのが望ましい
- 逆に「読み取り専用ツール」がブロックされたままだと、Claudeがファイル内容を確認せずに書き込む（＝中身を見ずに新規作成はできるが、既存ファイルの中身を踏まえた編集はできない）状態になる点にも注意
